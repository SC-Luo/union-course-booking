# 踩坑過程

本文件只記錄可重複避免的問題。不要貼完整聊天紀錄、私密金鑰、真實名冊或預約個資。

## 2026-08-05 Logo 在 production 消失

現象：
production 顯示名稱已改為「課程管理系統」，但畫面沒有出現工會 logo。使用者指出 logo 之前已經做過，但這次 production 更新後消失。

判斷：
前一次 logo 相關變更存在於本機 `firestore-diagnostics-preview` 工作區的未提交檔案中，例如 `public/brand/*` 與 `src/lib/brand.ts`，但沒有進入 `main`。這次先前 production 更新是從乾淨 `main` 工作樹做最小 metadata 改名，因此只部署了 `main` 裡存在的檔案，未提交的 logo 變更沒有被帶上 production。

解法：
將 logo 原始檔正式複製到 `public/brand/union-logo-full.png` 與 `public/brand/union-logo-mark.png`，新增 `src/lib/brand.ts` 作為品牌設定單一來源，並讓 `layout.tsx`、`StudentShell`、`AdminShell` 與後台登入頁都引用這份設定。

後續改進：
品牌、logo、production 顯示名稱都必須納入 Git 並推到 `main`。後續 AI 若看到「之前做過但 production 不見了」，先查 `git status --short`、`git branch -vv`、`git diff --stat` 與未追蹤檔案，不要假設本機工作區內容已經等於 production。

## 2026-08-05 課程調整送出後 production server error

現象：
後台調整課程主檔或年度課程後，畫面出現黑底錯誤頁 `This page couldn't load`。其中年度課程錯誤 digest 為 `2364232014`。

判斷：
Vercel logs 顯示 `POST /admin/course-offerings` 寫入 Firestore 時帶入 `code: undefined`，Firestore 不接受 `undefined` 欄位。另一筆 `POST /admin/course-masters` 則是 `defaultCourseMode: undefined`。Production 禁止 fallback 到本機 JSON，因此原本的 catch 嘗試 fallback 後仍丟出 server error。

解法：
在 `src/lib/booking-repository.ts` 的 Firestore 寫入點統一套用 `removeUndefinedFields()`，涵蓋分類、課程、課堂、課程主檔、年度課程、名冊關聯、學員課程紀錄、講師與預約補寫等資料。Production 寫入失敗時直接丟出明確的 Firestore required error，只有非 production 才 fallback 到本地 JSON。

後續改進：
任何新增 Firestore `.set()` / `.update()` 前，都要先確認 payload 不含 `undefined`。若欄位可空，使用 `undefined` 代表不寫入欄位，應在送 Firestore 前清掉；如果需要保留空值，應明確使用 `null`。
